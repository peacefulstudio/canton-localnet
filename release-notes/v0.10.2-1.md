# canton-localnet v0.10.2-1

The vendored Splice moves to 0.10.2 and the Canton inside to 3.7.3, with no change to the fixtures, the CLI or the action.

## What's new since v0.10.1-2

**Splice 0.10.2 on Canton 3.7.3.** A patch bump: ports, slots, env-var names and auth are unchanged, and the Daml SDK (3.5.2), the Splice DARs and the default protocol version (37) stay as they were. Upstream's compose tree changes in one place, the removal of the unused CometBFT block from the SV app config, and the vendored `sv-validator-1` config drops it too. Nothing in this repository set the variables that block read.

**The scan API carries the traffic-based app rewards amendment.** Scan's `/v0/events` responses gain `asset_activity_records` and `submitting_app_provider` on each event, `OpenMiningRoundSummary` gains four optional fields for the asset-side issuance ratio and reward coupons, and `POST /v0/reward-coupons-v2-disclosures` returns the created event blobs of active `RewardCouponV2` contracts. A client that reads the scan API can ignore the new fields or ingest them. The SV app also drops its CometBFT endpoints and metrics.

**New database migrations on an existing volume.** The validator and scan databases apply two Flyway migrations on start, and a stack started on 0.10.1 volumes came up ready with no container restart. On such a volume the scan app's reward computation logs an `ERROR` for each round opened before the upgrade, about every 30 seconds, and LocalNet works regardless. Recreate the volumes to start without those lines. The hosted-runner action and the Hetzner LocalNet VM start from fresh volumes, which hold no round from before the upgrade.
