# canton-localnet v0.10.3-1

The vendored Splice moves to 0.10.3 and the Canton inside to 3.7.4, `up` checks the Docker server version, and the fixtures and the action get a batch of correctness fixes.

## What's new since v0.10.2-1

**Splice 0.10.3 on Canton 3.7.4.** A patch bump: ports, slots, env-var names and auth are unchanged, and the Daml SDK (3.5.2), the Splice DARs and the default protocol version (37) stay as they were. The Postgres image moves to 18.7 and the nginx image to 1.31.9, each pinned by digest, and the JVM options of the `canton`, `splice` and `console` containers gain `-XX:-UseBASE64Intrinsics`, as upstream does. Postgres 18.7 is a minor release of the same major, so existing volumes read as is, and the Hetzner box's volume state key now records the Postgres major only, so a Postgres patch bump alone no longer wipes it. The scan API gains optional fields and an optional ACS snapshot pruning, and a client that reads it is unaffected.

**`make up` and `canton-localnet up` check the Docker server version.** Docker 28.0.0 fixed ports published to `127.0.0.1` being reachable from other hosts on the same network segment. On an older server, or one whose version cannot be read, both print a warning and still start the stack. `make up STRICT=true` fails instead. The documented minimum is now Docker 28.

**`canton-localnet wait-ready --since <time>`.** It bounds the restart check to the boot being waited on, so a container that restarted before that instant passes with a warning. The restart error no longer advises `down --volumes`, which wiped the ledger state, and points to `docker inspect`, `docker logs` and a `down` followed by `up` instead.

**Log redaction is broader.** The action's diagnostics and `make logs-recent` now also scrub `Authorization` headers, PEM private keys, `scheme://user:password@host` URIs and more credential assignments, and `cli: release` pins the build provenance check to the release tag.

## Upgrading

**`POSTGRES_HOST_PORT` is a bare host port.** `POSTGRES_HOST_PORT=5433 make up PQS=true` now works, where it failed with `invalid hostPort: 127.0.0.1`. The `HOST:CONTAINER` form that worked before, `POSTGRES_HOST_PORT=5433:5432`, now fails in compose with `invalid IP address`. Change it to `POSTGRES_HOST_PORT=5433`, and set `HOST_BIND_IP` for a bind address.

**The diagnostics artifacts have new names.** The action uploads `canton-localnet-diagnostics-<job>-<job-index>-<run-attempt>` and the teardown action `canton-localnet-teardown-diagnostics-<job>-<job-index>-<run-attempt>`, where `<job-index>` is `strategy.job-index` (`0` outside a matrix) and `<run-attempt>` is `github.run_attempt`. The legs of a matrix job and a re-run no longer collide on one name. A step that downloads an artifact by the old name must append `-<job-index>-<run-attempt>`, or download by the `canton-localnet-*diagnostics-*` pattern.

**Docker 28 or later.** On an older server `make up` and `canton-localnet up` warn, and `make up STRICT=true` fails. Upgrade the Docker server to 28.0.0 or later.

**Terraform 1.14 or later.** The `terraform/hetzner` and `terraform/github-oidc` modules required Terraform 1.11 before.

**`LocalnetFixture` is not an xUnit class fixture.** Its constructor is private: create it per test with `await using var fixture = LocalnetFixture.FromEnvironment();`, or wrap it in your own `IAsyncLifetime` class fixture. Nothing in its behaviour changed, and the `xunit` tag is gone from the NuGet package tags.

A stack on existing volumes picks up Postgres 18.7 when the `postgres` container is recreated (`canton-localnet down`, then `up`), and the data directory is read as is. A Hetzner box provisioned from `terraform/hetzner` wipes its volumes on its own, because its state key includes the Splice version.

## Fixed

- The C# and Go DAR uploaders count a package as vetted only while the clock is inside its validity window, so an expired or not yet started vetting no longer makes an upload succeed.
- The Go sample in the integration-testing guide calls `Setup` before `Endpoints`, so it skips with nothing up instead of panicking, and the Go samples report a `Teardown` error instead of dropping it.
- `ValidatorFixture.CreateUser` in Go returns an error once its `Fixture` has been torn down.
- The C# fixture bounds every response body it reads at 16 MiB, as the Go fixture does, and wraps an empty or malformed `2xx` body in `JsonLedgerApiException`.
- `DarUploader` and `PartyAllocator` retry the synchronizer discovery that precedes an upload or an allocation.
- The Go `DarUploader` rejects an empty DAR file, and the .NET `PartyAllocator` no longer throws `NullReferenceException` on a party entry with no `party`.
- Diagnostics artifacts from the legs of a matrix job or from a re-run no longer fail with a 409, and a failed diagnostics upload no longer fails a teardown whose `down --volumes` succeeded.
- `canton-localnet up --timeout` no longer reports `%!w(<nil>)` when compose succeeds just as the timeout expires, and on Windows it stops a cancelled `docker compose` at once.
- `canton-localnet env --pqs` quotes a PQS password that starts with a quote or has leading or trailing whitespace.
- `SECURITY.md` names the supported line, the latest published release, and no longer points at a `prod` branch.

The full list is in the `CHANGELOG.md`.
