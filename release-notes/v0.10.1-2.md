# canton-localnet v0.10.1-2

A boot that survives a self-healed Splice initialization restart on a starved runner, with Splice 0.10.1 and Canton 3.7.2 unchanged.

## What's new since v0.10.1-1

**A self-healed `splice` restart no longer fails the boot.** On a starved host such as a 2 vCPU runner, splice's first call to `canton` can pass its 60 s deadline, splice exits and `restart: always` brings it back healthy. `canton-localnet wait-ready` and the action's boot now accept exactly that restart and print a warning (a `::warning::` annotation under GitHub Actions) with the exit code and the `Caused by` line. A `canton` restart, an OOM kill or any other `splice` restart still fails, and the error now names the exit code, whether the container was OOM-killed and the last `Caused by` line.

**`canton-localnet up` rides out the same restart.** Docker reports the exited container as `unhealthy` until it restarts, so compose could abandon the boot, and Compose 5.1.3 then hung instead of exiting. `up` now stops compose, classifies the restart, and for the tolerated `splice` one warns and runs `docker compose up -d` once more within the remaining `--timeout`.

**The .NET fixture package now ships for `net10.0` and `net11.0`.** `Peaceful.Canton.Localnet.Testing` carries a `lib/net10.0` and a `lib/net11.0` asset, both compiled with C# 14. A `net10.0` project still restores and builds with only the .NET 10 SDK, and a `net11.0` project picks up the new asset. The `Microsoft.Extensions.*` dependencies are 10.0.15 on `net10.0` and 11.0.0 on `net11.0`.

**Consistent Microsoft.Extensions packages in the .NET fixture.** The package references `Microsoft.Extensions.Logging` directly, and on `net10.0` its Dependency Injection, Logging and Logging.Abstractions references move to 10.0.15 to match Http, so that asset ships one 10.0.x set. A consumer that pins these packages at 10.0.x restores without a downgrade error.

## Fixed

`canton-localnet up` no longer fails or hangs until `--timeout` when compose abandons the boot over a `splice` restart. The full list is in the `CHANGELOG.md`.
